# Atlas 产品走查与 v0.3.3 迭代

2026-11-08 · 范围：文章阅读、视频侧栏、设置、知识同步与数据操作。

这是一份基于产品说明、界面代码和文章端真实 Chrome 验证的启发式评审。视频播放、服务商实际延迟和新用户配置流程本轮未做完整实测；下面的影响判断属于设计判断，尚未经过用户访谈验证。

## 产品判断

Atlas 的价值是“帮助用户理解来源，并把自己的想法留下来”。这条路径的基础是可控的阅读显示、可信的保存反馈和容易找回的内容。建议围绕这些基础安排后续迭代。

## 本次落实：可撤回的阅读显示

- **T → … → ✓**：点击 T 直接开启翻译；… 表示请求处理中；✓ 表示译文显示状态。再次点击恢复原文显示。✓ 不代表译文质量或覆盖率认证；全部失败时显示 ! 并提供重试提示。
- 译文可见性与笔记数据独立。隐藏译文保留高亮、笔记和缓存，重新开启复用缓存，并收集新出现的正文。
- 翻译过程中关闭：当前请求仍可能完成并计费，其结果只写入缓存和隐藏节点；不继续发起后续批次。
- **⋯ 更多工具**：放置补译和批注管理。原来的 “Clear all” 改为明确的“删除此页笔记和高亮”，删除前确认范围。保留用户明确删除数据的能力。
- Escape 关闭工具菜单并返回工具按钮；开关具备稳定的名称与 `aria-pressed` 状态；提示消息具备 `role=status`。
- 本轮继续使用既有英文 UI 文案，未混入局部中文界面。

开关的名称、状态与操作反馈参考 [W3C 按钮模式](https://www.w3.org/WAI/ARIA/apg/patterns/button/)；不抢焦点的状态提示参考 [W3C 状态消息说明](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。

## 建议的迭代优先级

| 优先级 | 观察与依据 | 建议 | 如何验证 |
| --- | --- | --- | --- |
| 高 | 设置页首先呈现 Transcript 与 AI provider；文章翻译依赖独立 companion，入口被放进 Knowledge & local data。`options.html`、`PRODUCT.md` | 先让用户选择“读文章 / 看视频 / 保存笔记”，展示对应服务的就绪状态；为文章翻译提供明确入口与连接检查。 | 首次安装后，用户能识别自己所需的服务，并完成第一段翻译。 |
| 高 | 文章请求失败统一回退到空结果；原提示为 Setup needed，不能区分连接失败、授权失败或超时。`requestTranslations`、`translatePageOnce` | 传递结构化错误，分别提供“检查本地服务 / 更新密钥 / 重试”，保留已有成功结果；将完成与缺失数量持续展示。 | 模拟服务离线、密钥错误、超时和部分成功，每种状态都有明确下一步。 |
| 高 | 页面批注可以保存，但侧栏以视频为入口；当前 Library 关注观看记录。`sidepanel.html`、`PRODUCT.md` | 增加统一的“已保存”视图，按来源聚合文章高亮和视频笔记，支持回到原段落或时间戳。 | 保存一条文章笔记后，关闭来源页面，仍能从一个入口找到并返回来源。 |
| 中 | 文案使用 Saved / Synced / Obsidian synced，状态主要通过短暂 toast 呈现。`saveExcerptFromSelection` | 笔记列表持续展示“已存本地 / 已同步到哪些目的地 / 待重试”，同步失败不覆盖本地保存成功。 | 外部目的地离线时，用户仍能确认笔记已保存，并在恢复后重试。 |
| 中 | 产品面向中文读者，主要操作界面仍以英语呈现。`options.html`、`sidepanel.html`、文章工具文案 | 提供完整中英界面语言选择，统一“翻译 / 隐藏译文 / 重试 / 删除批注”的术语。 | 文章、视频、设置使用同一词表，无半页混合语言。 |
| 中 | 视频会在加载字幕后生成 Overview，并提前翻译；成本和服务依赖主要在文档解释。`PRODUCT.md` | 首次开启时清楚说明自动处理范围和费用来源；提供自动 / 手动处理偏好与当前处理状态。 | 用户能准确描述打开视频后会触发什么请求，并能找到关闭自动处理的入口。 |
| 后续 | 浮层已移到中下部，仍可能遇到网站侧边控件。`article-reader.css` | 支持记住拖动位置和“此网站隐藏”，保留浏览器工具栏入口以便恢复。 | 在有固定侧栏、客服按钮和窄屏页面上完成阅读操作。 |

## 边界与安排

本轮实现文章显示开关、进行中隐藏行为、缓存复用、清晰的批注删除和键盘/状态反馈；上表其他项目为后续建议，并未实现或宣称已验证。

建议下一轮先完成“按任务配置 + 可行动的失败状态”，之后做“统一已保存”。这两步直接改善首次成功和日常回访路径。

## 验证记录

- 新增测试先在旧代码上失败：无可见性状态，翻译中关闭后仍继续处理后续段落。
- `npm run check` 通过构建、类型检查、134 项测试和发布审计。
- DOM 回归测试验证：开关显示、原文恢复、高亮和笔记不变、缓存复用、晚到结果保持隐藏、关闭后暂停后续批次。
- 真实 Chrome 的固定测试页验证：显示/隐藏、复用缓存、保留批注、右上角控件可点击、桌面与 360px 窄屏菜单边界、Escape、取消批注删除。
- 真实测试页使用确定的翻译响应验证交互；服务商译文质量与实际网络延迟不在该测试覆盖范围内。
